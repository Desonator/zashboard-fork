# Инструменты проверки Zashboard

Zashboard — веб-панель для управления прокси и просмотра состояния Clash-совместимого API. Этот форк дополняет интерфейс Smart-весами, историей задержки и обновлением данных прокси. Каталог `test/` содержит локальные инструменты для проверки производительности и основных сценариев интерфейса.

Сценарии запускают собранную панель в Chrome и подключают её к тестовому API. Они не обращаются к реальному ядру и не проверяют конкретное поведение Prizrak-Core или Smart API. Для проверки Smart-весов и `ping-config` нужен совместимый ответ настоящего ядра либо отдельная фикстура с такими полями.

## Требования

- Node.js 22 или новее;
- pnpm;
- Chrome или Chromium. Скрипты ищут браузер в `PATH`; при необходимости задайте `CHROME_BIN`.

Перед запуском браузерных сценариев соберите приложение:

```sh
pnpm install --frozen-lockfile
pnpm build
```

## Нагрузочный замер

Запустите `pnpm test:bench`, чтобы измерить первую отрисовку карточек, объём DOM и работу прокрутки на искусственной конфигурации:

```sh
pnpm test:bench
pnpm test:bench --groups 300 --nodes 200 --conns 1000
pnpm test:bench --cpu 10 --repeat 5
```

Параметры:

| Параметр | По умолчанию | Назначение |
| --- | ---: | --- |
| `--groups` | 150 | Количество групп прокси |
| `--nodes` | 60 | Количество узлов в каждой группе |
| `--conns` | 300 | Количество активных подключений |
| `--cpu` | 1 | Коэффициент ограничения CPU в Chrome; `10` означает примерно одну десятую скорости |
| `--repeat` | 3 | Количество прогонов; итоговые сравнения делайте по медиане |
| `--width`, `--height` | 1440, 900 | Размер viewport |
| `--mobile` | выкл. | Включает мобильный режим эмуляции |
| `--url` | — | Использует уже запущенный сайт вместо локального статического сервера |
| `--json` | выкл. | Выводит результаты в JSON |
| `--headful` | выкл. | Открывает обычное окно Chrome вместо headless-режима |

Пример мобильного замера:

```sh
pnpm test:bench --width 390 --height 844 --mobile --cpu 10
```

Для сравнения двух изменений запускайте одинаковые параметры на одной машине и на одинаковой сборке браузера.

## Поведенческая проверка

`pnpm test:verify` проверяет виртуальный список прокси и основные взаимодействия:

```sh
pnpm test:verify
pnpm test:verify --groups 100 --nodes 50 --conns 1000
```

Сценарий проверяет, что карточки монтируются по мере прокрутки и удаляются за пределами экрана, фильтрация и раскрытие групп работают, положение страницы восстанавливается, а изменения задержки отражаются в интерфейсе. При ошибке команда завершается с ненулевым кодом.

## Подключение к API при первом запуске

`pnpm test:setup` проверяет параметры URL, автоматическое подключение к API по origin страницы и резервное подключение к `127.0.0.1:9090`:

```sh
pnpm test:setup
```

Тест использует локальные mock-серверы и проверяет успешный ответ, запрос секрета, отказ авторизации, некорректный ответ и недоступность API. Настоящее ядро и его конфигурация не затрагиваются.

## Анимация сворачивания групп

Этот сценарий проверяет последовательность анимации, параллельное сворачивание карточек, быструю смену направления и очистку временных элементов:

```sh
node test/collapse.mjs
```

Перед запуском требуется `pnpm build`.

## Тестовый API вручную

Чтобы открыть панель и подключиться к искусственному Clash API:

```sh
node test/mock-server.mjs --groups 150 --nodes 60 --conns 300 --port 9999
pnpm dev
```

В панели добавьте backend `http://127.0.0.1:9999` без секрета. Mock-сервер реализует используемые панелью базовые endpoint-ы прокси, провайдеров, правил, конфигурации и подключений, а также WebSocket-ы трафика, памяти и подключений.

## Ограничения и структура

Mock API нужен для проверки базового интерфейса и его производительности. Он не воспроизводит все расширения конкретных ядер, включая Smart-веса, историю `ping-config` и формат дополнительных статусов передачи данных. Успешное прохождение тестов не заменяет проверку этих функций на целевом ядре.

```text
test/
  bench.mjs             нагрузочный замер
  verify.mjs            поведенческие проверки страницы прокси
  setup.mjs             сценарии начального подключения
  collapse.mjs          проверки анимации карточек
  mock-server.mjs       тестовый Clash API
  lib/                  Chrome/CDP, HTTP-сервер и тестовый harness
```
